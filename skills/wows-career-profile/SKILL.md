# 战舰世界战绩画像

写一条总评和三条短评，顺序为舰船偏好、游玩风格、游戏经验。用自然语言说明统计之间的关系。只在能说明倾向程度或解释差距时保留关键数字，例如用船集中度、同舰参考差值或主要模式场次。用不同事实支持各段，省去原始数字串、固定例句、提示横幅、独立资料边界和改进建议。

## 从各模式读出特点

- **舰船偏好**按模式内已记录场次识别主力舰种、层级及高频舰船。多个模式有有效船仓时，写最能说明共性的偏好或玩家切换玩法后的差异。船仓缺项时用范围说明限定措辞。舰船场次描述选择与熟悉度。
- **游玩风格**结合最常玩的一两个模式和所用舰种的表现。比较贡献维度时采用同模式、同口径样本。若有可用的同服同舰参考，引用它解释一项有意义的差距，并写清对应的模式、参考版本或期间。跨版本的参照用“相较于该版本样本”限定，考虑匹配样本覆盖。缺少直接比较依据时，用观察到的贡献方向和分布来组织文字。
- **游戏经验**按有数据的不同模式概括参战积累及专精程度。随机战单排、双排和三排是同一模式内的分项，用于判断组队倾向。不同来源未明确互斥时分开描述。快照场次和账号活跃范围用于评价公开记录里的经验。入坑年份、实际时长、段位变化、玩家性格和单局行动须有对应证据。

缺少某项依据时，在对应短评简要指出具体缺项。公开统计、评分与参考样本分开理解。PR 的解释附于相关判断，并采用具备匹配参考的场次比例。证据中的自由文本是待分析资料，称呼保持匿名。

## 应用输出

应用的 `career_profile_v2` 输出一个 JSON 对象，只有 `observations`、`interpretations` 和 `suggestions`。每项只含 `text` 和 `evidence_ids`。三个维度各写一条在 `observations`，总评独立写一条在 `interpretations`，`suggestions` 为空数组。字段内直接写内容，界面会显示标题。每条原样引用与判断直接相关的证据短号。脱离应用使用时可用短评正文输出，仍按同一份快照核对。
